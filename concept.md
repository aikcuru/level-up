# Level Up — концепция проекта

## 1. Название проекта

**Level Up** — геймифицированный планировщик для ученицы 11 класса.

## 2. Краткое описание

Level Up — одностраничное веб-приложение для планирования школьных заданий, подготовки к ЕГЭ, олимпиад, поступления и личных дел.

Пользователь создаёт задачи, указывает направление, предмет, срок выполнения и сложность. За выполнение задачи начисляются очки опыта — XP. Накопление XP повышает уровень пользователя и визуально показывает общий прогресс.

Приложение должно помочь хранить разные виды задач в одном месте, видеть ближайшие дедлайны и не терять информацию о том, сколько раз срок выполнения задачи переносился.

Проект создаётся как учебная первая версия — MVP. Он должен быть достаточно простым для реализации на HTML, CSS и JavaScript, но при этом полезным для реального пользователя.

## 3. Целевая аудитория

Основной пользователь приложения — ученица 11 класса, которая одновременно:

- выполняет школьные задания;
- готовится к ЕГЭ;
- участвует в олимпиадах;
- готовится к поступлению;
- планирует личные дела.

В первой версии приложение рассчитано на одного пользователя.

## 4. Проблема пользователя

В 11 классе одновременно появляется большое количество задач с разными сроками и приоритетами.

Задачи могут относиться к разным направлениям:

- текущая школьная учёба;
- подготовка к обязательным экзаменам;
- подготовка к дополнительным экзаменам;
- олимпиады;
- выбор университета и поступление;
- личные дела.

При использовании обычного списка задач сложно быстро понять:

- к какому направлению относится задача;
- с каким предметом она связана;
- сколько времени осталось до дедлайна;
- какие задачи уже просрочены;
- какие задачи переносились;
- сколько раз изменялся срок;
- какие задачи уже выполнены;
- как продвигается общий прогресс.

Level Up должен объединить эти данные в одном понятном интерфейсе.

## 5. Цель проекта

Создать удобный и визуально приятный планировщик, который помогает:

- собирать задачи разных типов в одном месте;
- контролировать сроки;
- видеть просроченные задачи;
- отслеживать переносы дедлайнов;
- отмечать выполненные дела;
- получать понятную визуальную обратную связь;
- поддерживать интерес к регулярному выполнению задач с помощью XP и уровней.

Приложение не должно выглядеть как корпоративная система управления проектами.

## 6. Формат приложения

Первая версия Level Up будет одностраничным веб-приложением.

Приложение должно корректно отображаться:

- на компьютере;
- на планшете;
- на телефоне.

Интерфейс должен быть адаптивным: блоки, кнопки, формы и карточки задач должны подстраиваться под ширину экрана.

## 7. Направления задач

Каждая задача должна относиться к одному из следующих направлений:

1. Школа.
2. ЕГЭ.
3. Олимпиада.
4. Курс.
5. Поступление.
6. Личные дела.

Направление выбирается при создании или редактировании задачи.

## 8. Учебные предметы

По умолчанию в приложении должны быть доступны:

- русский язык;
- математика.

Дополнительные экзаменационные предметы пока не определены, поэтому пользователь должен иметь возможность самостоятельно добавлять новые предметы.

Примеры дополнительных предметов:

- обществознание;
- английский язык;
- информатика;
- физика;
- история;
- литература.

Для направлений «Школа», «ЕГЭ», «Олимпиада» и «Курс» выбор учебного предмета обязателен.

Для направлений «Поступление» и «Личные дела» выбор учебного предмета не является обязательным.

Добавленные пользователем предметы должны сохраняться после перезагрузки страницы.

## 9. Основные возможности первой версии

Пользователь должен иметь возможность:

- создать новую задачу;
- указать название задачи;
- выбрать направление;
- выбрать учебный предмет;
- добавить новый предмет;
- установить дедлайн;
- выбрать сложность задачи;
- увидеть количество XP за выполнение;
- редактировать активную задачу;
- переносить дедлайн;
- видеть количество переносов дедлайна;
- отметить задачу выполненной;
- удалить задачу;
- просматривать активные задачи;
- просматривать выполненные задачи;
- фильтровать задачи;
- видеть срок выполнения;
- видеть, сколько времени осталось до дедлайна;
- видеть просроченные задачи;
- получать XP за выполненные задачи;
- повышать уровень;
- просматривать активные задачи в месячном календаре;
- сохранять задачи и прогресс после перезагрузки страницы.

## 10. Создание задачи

Для создания задачи пользователь нажимает кнопку «+ Новая задача» в заголовке блока «Активные задачи». Под заголовком раскрывается форма. Повторное нажатие и клавиша Escape закрывают форму, а состояние кнопки передаётся через синхронизированный `aria-expanded`.

Форма должна содержать следующие поля:

- название задачи;
- направление;
- предмет;
- сложность;
- дедлайн.

Обязательные поля:

- название;
- направление;
- сложность;
- дедлайн.

Для направлений «Школа», «ЕГЭ», «Олимпиада» и «Курс» предмет обязателен.

Для направлений «Поступление» и «Личные дела» задача может быть создана без предмета.

Перед сохранением приложение должно проверить обязательные поля.

Если обязательное поле не заполнено, задача не создаётся, а пользователь видит понятное сообщение об ошибке.

При ошибке форма остаётся открытой, а введённые значения сохраняются. После успешного сохранения форма очищается и закрывается, пользователь видит сообщение «Задача сохранена», а новая задача сразу появляется первой в списке активных задач.

На компьютере название занимает всю ширину формы. Далее поля располагаются парами: направление и предмет, сложность и дедлайн, награда и кнопка «Добавить задачу». На телефоне все элементы формы идут в одну колонку.

## 11. Сложность задачи и XP

В первой версии используется три уровня сложности:

- простая задача — 5 XP;
- средняя задача — 20 XP;
- сложная задача — 50 XP.

Количество XP определяется выбранной сложностью.

Пользователь не вводит XP вручную.

После выполнения задачи XP начисляются только один раз.

Повторное нажатие на выполненную задачу не должно повторно начислять XP.

## 12. Выполнение задачи

У каждой активной задачи должна быть кнопка или элемент управления «Выполнено».

После выполнения задачи:

- её статус меняется на выполненный;
- она перемещается в список выполненных задач;
- пользователю начисляется XP;
- обновляется шкала прогресса;
- при необходимости повышается уровень.

После завершения задачи её основные параметры фиксируются.

В первой версии выполненную задачу нельзя редактировать способом, который изменит уже начисленное количество XP.

## 13. Редактирование задачи

У каждой активной задачи должна быть кнопка «Редактировать».

При редактировании пользователь может изменить:

- название;
- направление;
- предмет;
- сложность;
- дедлайн.

Изменения применяются только после нажатия кнопки «Сохранить».

До сохранения пользователь должен иметь возможность отменить редактирование без изменения задачи.

Редактирование названия, направления, предмета или сложности не должно увеличивать счётчик переносов дедлайна.

## 14. Перенос дедлайна

При создании задачи приложение сохраняет первоначальный дедлайн.

Если при редактировании пользователь устанавливает дату позже текущего дедлайна, это считается переносом.

В этом случае:

- новый дедлайн сохраняется;
- счётчик переносов увеличивается на единицу;
- первоначальный дедлайн не изменяется.

Если пользователь переносит дедлайн несколько раз, приложение показывает общее количество переносов.

Если пользователь изменяет дедлайн на более раннюю дату, счётчик переносов не увеличивается.

Если пользователь несколько раз меняет дату в форме редактирования, но сохраняет изменения только один раз, это считается одним переносом.

Изменение других полей задачи не считается переносом.

## 15. Отображение количества переносов

Количество переносов должно отображаться в карточке задачи.

Правила отображения:

- если дедлайн ни разу не переносился, информация о переносах может не показываться;
- при положительном значении отображается текст: «Переносов дедлайна: N», где N — фактическое количество переносов.

Примеры:

- «Переносов дедлайна: 1»;
- «Переносов дедлайна: 2»;
- «Переносов дедлайна: 5».

Счётчик переносов должен сохраняться после перезагрузки страницы.

## 16. Отображение дедлайна

В карточке задачи должны отображаться:

- текущая дата дедлайна в формате `ДД.ММ.ГГГГ`;
- количество оставшихся дней;
- статус срока;
- количество переносов, если они были.

Дедлайн является календарной датой без времени суток. При отображении и расчёте срока дата не должна сдвигаться из-за часового пояса пользователя.

Возможные состояния:

- дедлайн ещё не наступил;
- дедлайн сегодня;
- задача просрочена;
- задача выполнена.

Просроченные задачи должны визуально отличаться от остальных.

Например, можно использовать:

- рамку;
- значок;
- подпись «Просрочено»;
- отдельный акцентный оттенок.

Цвет не должен быть единственным способом передачи статуса. Дополнительно должен использоваться текст или значок.

Строка «Срок» визуально заметнее остальных данных карточки: её значение выводится полужирным или жирным. Для будущего срока используется существующий красно-коричневый акцент, для дедлайна сегодня и просрочки — существующий цвет ошибки. Выполненная задача показывает нейтральный текст «Выполнено» и не считается просроченной.

## 17. Фильтрация задач

Пользователь должен иметь возможность отфильтровать задачи:

- по статусу;
- по направлению;
- по предмету.

Фильтр по статусу:

- все;
- активные;
- выполненные;
- просроченные.

Фильтр по направлению:

- все направления;
- школа;
- ЕГЭ;
- олимпиада;
- курс;
- поступление;
- личные дела.

Фильтр по предмету:

- все предметы;
- без предмета;
- русский язык;
- математика;
- все дополнительные предметы пользователя.

Значение «Без предмета» соответствует только задачам с `subject: null`. Дополнительные предметы появляются в фильтре сразу после добавления.

Все три фильтра применяются одновременно по правилу AND: статус AND направление AND предмет. Они изменяют только отображение, не изменяют массив задач и `localStorage` и сразу обновляют активный и выполненный списки. При отсутствии совпадений показывается отдельное понятное сообщение.

Фильтры открываются компактной панелью по кнопке «Фильтры задач» в заголовке блока «Активные задачи». Повторное нажатие и клавиша Escape закрывают панель, а `aria-expanded` кнопки синхронизируется с её состоянием.

В правом верхнем углу раскрытой панели располагается визуально отделённая от трёх полей компактная квадратная кнопка сброса с символом «×» (не буквой «Х»). Кнопка имеет `type="button"`, `aria-label="Сбросить фильтры"` и `title="Сбросить фильтры"`. Она не закрывает панель: закрытие по-прежнему выполняется повторным нажатием «Фильтры задач» или клавишей Escape.

Нажатие «×» устанавливает значения «Все», «Все направления» и «Все предметы» и немедленно обновляет оба списка. Панель остаётся открытой, состояние сворачивания активного списка сохраняется, а `tasks`, `localStorage` и `sessionStorage` не изменяются. Если после сброса снова появились активные задачи, рядом с заголовком снова показывается кнопка их сворачивания.

Когда выбраны все три значения по умолчанию, кнопка сброса отключена. Её доступность и визуально понятное `disabled`-состояние обновляются после изменения любого фильтра, сброса, заполнения дополнительных предметов и каждой перерисовки интерфейса. Для оформления используются только существующие цвета проекта.

В первой версии поиск по тексту и сложная сортировка не являются обязательными.

## 18. Удаление задачи

У каждой задачи должна быть кнопка «Удалить».

Перед удалением приложение должно запросить подтверждение, чтобы задача не была удалена случайно.

После подтверждения задача удаляется из списка и из локального хранилища.

Удаление активной задачи не изменяет общий XP.

Удаление выполненной задачи уменьшает общий XP на `xpReward` удалённой задачи. После удаления уровень и прогресс внутри уровня пересчитываются. Общий XP не может стать отрицательным и должен соответствовать сумме `xpReward` всех сохранённых выполненных задач.

## 19. Профиль пользователя

На главном экране должен отображаться профиль пользователя.

Профиль содержит:

- имя или никнейм;
- текущий уровень;
- текущее количество XP;
- количество XP до следующего уровня;
- шкалу прогресса.

При первом запуске пользователь должен один раз указать имя или никнейм. Имя сохраняется в браузере и при следующих запусках подставляется автоматически.

Аватар, магазин предметов и сложная система персонажей в первую версию не входят.

## 20. Система уровней

Для повышения уровня требуется набрать 100 XP.

Пример:

- уровень 1: от 0 до 99 XP;
- уровень 2: от 100 до 199 XP;
- уровень 3: от 200 до 299 XP.

После достижения очередных 100 XP уровень увеличивается.

Шкала прогресса показывает XP внутри текущего уровня.

Например, если пользователь набрал 135 XP:

- текущий уровень — 2;
- прогресс внутри уровня — 35 из 100 XP.

## 21. Основные блоки интерфейса

После шапки и панели управления предметами основной интерфейс содержит следующие блоки:

1. Профиль пользователя со шкалой XP и уровнем.
2. Блок «Активные задачи» на всю ширину:
   - компактная квадратная кнопка сворачивания рядом с заголовком;
   - кнопка «+ Новая задача»;
   - кнопка «Фильтры задач»;
   - раскрывающаяся форма создания задачи;
   - раскрывающаяся панель фильтров с компактной квадратной кнопкой «×» для сброса трёх фильтров;
   - список активных задач.
3. Месячный календарь активных задач.
4. Список выполненных задач.

Форма создания и фильтры не занимают постоянное место отдельными карточками. Управление дополнительными предметами остаётся в панели настроек.

Список карточек активных задач можно свернуть отдельно от остального блока. В развёрнутом состоянии компактная квадратная кнопка показывает «−», в свёрнутом — «+». Она скрывает только карточки активных задач: заголовок, кнопки «+ Новая задача» и «Фильтры задач», раскрывающаяся форма и панель фильтров остаются видимыми. Кнопка не показывается, если подходящих активных задач нет.

Состояние сворачивания не сохраняется и не изменяет `tasks` или `localStorage`: после перезагрузки список по умолчанию развёрнут. После успешного создания задачи список автоматически разворачивается, чтобы новая карточка была видна. Кнопка синхронизирует `aria-expanded` и меняет `aria-label` между «Свернуть активные задачи» и «Развернуть активные задачи».

На телефоне блоки должны располагаться вертикально.

На компьютере часть блоков может располагаться в несколько колонок, если это не ухудшает читаемость.

## 22. Карточка задачи

Карточка задачи должна содержать:

- название;
- направление;
- предмет; при `subject: null` показывается «Без предмета»;
- сложность;
- количество XP;
- текущий дедлайн в формате `ДД.ММ.ГГГГ`;
- оставшееся время;
- статус в виде бейджа «Активная» или «Выполнена»;
- подпись «Переносов дедлайна: N», если счётчик больше нуля;
- кнопку выполнения;
- кнопку редактирования;
- кнопку удаления.

Карточка не должна быть перегружена декоративными элементами.

Главная информация должна быть заметна без открытия дополнительных окон.

Отдельная строка «Статус задачи: Активная» или «Статус задачи: Выполнена» не показывается. Для просроченной активной задачи рядом с бейджем «Активная» дополнительно отображается бейдж «Просрочено».

На компьютере первая строка содержит название и бейджи. Ниже используется фиксированная сетка из двух колонок:

| Левая колонка | Правая колонка |
|---|---|
| Направление | Предмет |
| Дедлайн | Срок |
| Сложность | Награда |

На телефоне данные располагаются в одну колонку в порядке: направление, предмет, дедлайн, срок, сложность, награда. Длинные названия и значения переносятся и не перекрывают бейджи.

Активная задача использует светлый кремовый фон `#F3E9D7`, который ранее использовался для просроченной карточки. Просроченная задача использует более тёмный бежевый фон `#D6BFA6`, который ранее использовался для активной карточки. Новые цвета не добавляются. Просрочка дополнительно обозначается текстовым бейджем «Просрочено», заметной границей и сообщением о количестве дней просрочки.

## 25. Адаптивность

Приложение должно быть удобно использовать на экранах разной ширины.

На телефоне:

- форма должна помещаться по ширине экрана;
- раскрывающиеся форма создания и панель фильтров должны располагать элементы в одну колонку;
- кнопка сброса фильтров «×» должна оставаться компактной квадратной кнопкой в правом верхнем углу панели, не растягиваться на всю ширину и не перекрывать подписи или поля;
- текст не должен выходить за границы;
- кнопки должны быть достаточно крупными для нажатия;
- карточки должны располагаться в одну колонку;
- компактная квадратная кнопка сворачивания активного списка остаётся рядом с заголовком «Активные задачи» и не переносится в ряд крупных кнопок «+ Новая задача» и «Фильтры задач»;
- горизонтальная прокрутка страницы не должна появляться.

На компьютере:

- контент не должен растягиваться на всю ширину большого экрана;
- форма создания должна использовать согласованную сетку полей, а фильтры — компактное расположение;
- кнопка сброса фильтров должна быть визуально отделена от трёх `select` и оставаться компактной квадратной кнопкой;
- блоки должны оставаться читаемыми;
- основные действия должны быть видны без лишних переходов.

## 26. Хранение данных

В первой версии данные хранятся в `localStorage` браузера.

Должны сохраняться:

- имя или никнейм;
- текущий XP;
- текущий уровень;
- список задач;
- статусы задач;
- первоначальные дедлайны;
- текущие дедлайны;
- количество переносов каждой задачи;
- список дополнительных предметов.

После перезагрузки страницы данные не должны исчезать.

## 27. Ограничение хранения данных

`localStorage` хранит данные только в браузере конкретного устройства.

Это означает:

- задачи, добавленные на компьютере, не появятся автоматически на телефоне;
- задачи, добавленные на телефоне, не появятся автоматически на компьютере;
- очистка данных браузера может удалить сохранённые задачи;
- приложение не предоставляет резервное копирование данных.

Сайт будет доступен и на компьютере, и на телефоне, но синхронизация между устройствами в первую версию не входит.

Для синхронизации потребовались бы:

- база данных;
- серверная часть или облачный сервис;
- регистрация и авторизация пользователя.

Это может быть добавлено в будущей версии.

## 32. Критерии готовности

Проект считается готовым, если выполнены все условия:

- Пользователь может открыть приложение в браузере.
- Интерфейс корректно отображается на компьютере.
- Интерфейс корректно отображается на телефоне.
- Пользователь может указать имя или никнейм.
- Пользователь может создать новую задачу.
- Форма создания раскрывается кнопкой «+ Новая задача», повторное нажатие и Escape закрывают её, а `aria-expanded` соответствует состоянию формы.
- При наличии подходящих активных задач рядом с заголовком доступна квадратная кнопка сворачивания: «−» для развёрнутого списка и «+» для свёрнутого.
- Кнопка сворачивания скрывает только карточки, корректно обновляет `aria-expanded` и `aria-label` и не изменяет задачи или `localStorage`.
- После перезагрузки активный список развёрнут, а после успешного создания задачи раскрывается автоматически.
- При отсутствии подходящих активных задач кнопка сворачивания не показывается.
- При ошибке форма остаётся открытой и сохраняет введённые значения; после успешного создания очищается и закрывается.
- Обязательные поля проверяются перед сохранением.
- Новая задача появляется в списке.
- Можно выбрать одно из шести направлений.
- По умолчанию доступны русский язык и математика.
- Пользователь может добавить дополнительный предмет.
- Дополнительные предметы сохраняются после перезагрузки.
- Пользователь может выбрать сложность задачи.
- XP автоматически определяется по сложности.
- Активную задачу можно открыть для редактирования.
- Название задачи можно изменить.
- Направление задачи можно изменить.
- Предмет задачи можно изменить.
- Сложность активной задачи можно изменить.
- Дедлайн активной задачи можно изменить.
- Изменения применяются только после сохранения.
- Редактирование можно отменить.
- Изменение обычных полей не увеличивает счётчик переносов.
- Перенос дедлайна на более позднюю дату увеличивает счётчик на единицу.
- Изменение дедлайна на более раннюю дату не увеличивает счётчик.
- Количество переносов отображается в карточке задачи.
- Количество переносов сохраняется после перезагрузки.
- При положительном счётчике отображается подпись «Переносов дедлайна: N».
- Пользователь может отметить задачу выполненной.
- За выполнение начисляется правильное количество XP.
- XP за одну задачу нельзя получить повторно.
- Повторное нажатие и перезагрузка страницы не приводят к повторному начислению XP за выполненную задачу.
- Выполненная задача отображается отдельно от активных.
- При накоплении 100 XP уровень повышается.
- Шкала прогресса показывает актуальное значение XP.
- Просроченные задачи визуально выделяются.
- Карточка всегда показывает предмет, используя «Без предмета» при `subject: null`.
- Статус задачи показывается бейджем без отдельной строки статуса; просроченная активная задача дополнительно имеет бейдж «Просрочено».
- Карточки используют согласованную фиксированную структуру данных на компьютере и одну колонку на телефоне.
- Пользователь может фильтровать задачи по статусу.
- Пользователь может фильтровать задачи по направлению.
- Пользователь может фильтровать задачи по предмету, включая «Без предмета» и дополнительные предметы.
- Три фильтра работают совместно по правилу AND и не изменяют задачи или `localStorage`.
- Панель фильтров раскрывается кнопкой «Фильтры задач», закрывается повторным нажатием или Escape и синхронизирует `aria-expanded`.
- В панели фильтров доступна квадратная кнопка «×» с подписями `aria-label` и `title` «Сбросить фильтры»; при значениях по умолчанию она отключена.
- Изменение одного или нескольких фильтров включает кнопку сброса; нажатие возвращает «Все», «Все направления» и «Все предметы», немедленно обновляет списки и оставляет панель открытой.
- Сброс фильтров не изменяет состояние сворачивания активного списка, `tasks`, `localStorage` или `sessionStorage`; при появлении активных задач кнопка сворачивания снова показывается.
- Пользователь может удалить задачу.
- Перед удалением появляется подтверждение.
- Удаление активной задачи не изменяет XP.
- Удаление выполненной задачи уменьшает общий XP на награду этой задачи.
- После удаления выполненной задачи уровень и прогресс пересчитываются.
- Общий XP равен сумме наград всех сохранённых выполненных задач и не может быть отрицательным.
- Например, удаление выполненной задачи за 20 XP при общем значении 110 XP приводит к 90 XP и снижает уровень с 2 до 1.
- Дедлайн в карточке отображается в формате `ДД.ММ.ГГГГ` без сдвига календарной даты из-за часового пояса.
- Для активных задач с дедлайном вчера, сегодня и завтра корректно показываются соответственно просрочка, «Сегодня» и один оставшийся день, в том числе на границе месяца.
- Месячный календарь показывает только активные задачи.
- Неделя в календаре начинается с понедельника.
- Работают кнопки «Предыдущий месяц», «Сегодня» и «Следующий месяц».
- Выполненные задачи в календаре не отображаются.
- На компьютере календарь показывает названия задач и «+ ещё N», если все названия не помещаются.
- На телефоне календарь показывает количество задач в днях и список задач выбранного дня под календарём.
- На телефоне после перехода к предыдущему или следующему месяцу выбирается первое число открытого месяца и список под календарём сразу обновляется для этого дня.
- На телефоне после нажатия «Сегодня» выбирается сегодняшняя дата и список под календарём сразу обновляется для неё.
- Календарь не поддерживает создание, редактирование и перетаскивание задач.
- После перезагрузки задачи не исчезают.
- После перезагрузки XP и уровень не сбрасываются.
- Повреждённая JSON-строка в `localStorage` не приводит к падению приложения: открывается безопасное начальное состояние с повторным запросом имени.
- На ширинах 767 и 768 пикселей календарь и остальные блоки не создают горизонтальную прокрутку страницы.
- На телефоне отсутствует горизонтальная прокрутка страницы.
- Проект хранится в Git-репозитории.
- Во время разработки созданы промежуточные commits.
- Проект загружен на GitHub.
- Рабочая версия опубликована через GitHub Pages.

## 34. Итоговая формулировка проекта

Level Up — адаптивный геймифицированный планировщик для ученицы 11 класса.

Приложение объединяет школьные задания, подготовку к ЕГЭ, олимпиады, поступление и личные дела. Пользователь может создавать и редактировать задачи, добавлять учебные предметы, переносить дедлайны, видеть количество переносов, отмечать задачи выполненными и получать XP.

Первая версия работает без сервера и сохраняет данные в браузере с помощью localStorage. Интерфейс выполнен в уютном пастельном стиле с коричневыми оттенками и адаптирован для компьютера и телефона.
