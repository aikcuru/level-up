# Техническое задание: Level Up

## 1. Общая информация

**Level Up** — одностраничный геймифицированный планировщик для одной ученицы 11 класса. Приложение объединяет школьные задания, подготовку к ЕГЭ и олимпиадам, курсы, поступление и личные дела.

Пользователь создаёт задачи, контролирует дедлайны, отмечает выполнение и получает XP. За каждые 100 XP повышается уровень.

## 2. Цель MVP

Создать простое адаптивное веб-приложение, которое позволяет одному пользователю:

- один раз указать имя при первом запуске;
- создавать и хранить задачи разных направлений;
- редактировать активные задачи;
- контролировать текущие и просроченные дедлайны;
- учитывать количество переносов дедлайна;
- завершать и удалять задачи;
- получать XP и повышать уровень;
- фильтровать задачи;
- сохранять данные после перезагрузки страницы.

## 3. Технические ограничения

Приложение должно быть реализовано без сборщика и состоять из трёх основных файлов в корне проекта:

```text
level-up/
├── index.html
├── style.css
└── script.js
```

Документация (`concept.md`, `tz.md`, `README.md`) может находиться рядом, но не является частью исполняемого приложения.

Разрешены только:

- HTML5;
- CSS3;
- нативный JavaScript;
- `localStorage` браузера.

Запрещены React, Vue, другие фреймворки, сервер, база данных, регистрация, авторизация, платные API и внешние системы управления состоянием. Приложение должно открываться как обычная статическая страница и подходить для публикации на GitHub Pages.

## 4. Пользователь и первый запуск

В MVP существует один локальный пользователь без учётной записи.

При первом запуске, если имя ещё не сохранено:

1. Основной интерфейс задач недоступен.
2. Пользователь видит стартовую форму с полем «Имя или никнейм» и кнопкой «Начать».
3. Имя обязательно. Перед проверкой пробелы в начале и конце удаляются.
4. Строка, состоящая только из пробелов, считается пустой.
5. При пустом значении форма не закрывается, данные не сохраняются, рядом с полем показывается понятная ошибка.
6. При корректном значении имя сохраняется в `localStorage`, стартовая форма скрывается и открывается основной интерфейс.

При следующих загрузках сохранённое имя отображается автоматически, а стартовая форма не показывается. Изменение имени и создание нескольких профилей в MVP не предусмотрены. После очистки `localStorage` приложение снова считается запущенным впервые.

## 5. Состав интерфейса

Страница должна содержать:

1. Стартовую форму ввода имени, показываемую только при первом запуске.
2. Шапку с названием Level Up и кнопкой настроек.
3. Профиль пользователя:
   - имя;
   - текущий уровень;
   - общий XP;
   - XP внутри текущего уровня;
   - количество XP до следующего уровня;
   - шкалу прогресса от 0 до 100 XP.
4. Блок «Активные задачи» на всю доступную ширину:
   - компактную квадратную кнопку сворачивания рядом с заголовком «Активные задачи»;
   - кнопку «+ Новая задача» в заголовке;
   - кнопку «Фильтры задач» в заголовке;
   - раскрывающуюся форму создания задачи;
   - раскрывающуюся компактную панель трёх фильтров с отдельной квадратной кнопкой их сброса;
   - список активных задач.
5. Обзорный месячный календарь активных задач.
6. Список выполненных задач.
7. Панель управления дополнительными предметами, открываемую из настроек и не занимающую постоянное место в основном потоке.
8. Понятные сообщения о пустом результате фильтрации или отсутствии задач.

Основной порядок блоков после шапки: профиль, блок «Активные задачи», календарь, выполненные задачи. Отдельные постоянно видимые карточки «Новая задача» и «Фильтры» отсутствуют. На телефоне все основные блоки и содержимое раскрывающихся панелей располагаются вертикально.

Кнопка сворачивания управляет только областью карточек активных задач:

1. Когда список развёрнут, кнопка показывает символ `−`, имеет `aria-expanded="true"` и `aria-label="Свернуть активные задачи"`.
2. Когда список свёрнут, кнопка показывает символ `+`, имеет `aria-expanded="false"` и `aria-label="Развернуть активные задачи"`.
3. Заголовок, кнопки «+ Новая задача» и «Фильтры задач», форма создания и панель фильтров при сворачивании не скрываются.
4. При отсутствии подходящих активных задач кнопка не показывается.
5. Сворачивание изменяет только представление и не меняет `tasks` или `localStorage`.
6. Состояние сворачивания не сохраняется: после каждой перезагрузки список по умолчанию развёрнут.
7. После успешного создания новой задачи список автоматически разворачивается, чтобы первая новая карточка была видна.

Для создания и редактирования используется одна общая форма. По умолчанию она работает в режиме создания. После нажатия «Редактировать» форма заполняется данными выбранной задачи, заголовок и основная кнопка меняются на режим редактирования, появляется кнопка «Отмена». Одновременно можно редактировать только одну задачу; до сохранения или отмены форма не создаёт новую задачу.

## 6. Направления задач

Допустимы ровно шесть направлений:

1. `Школа`;
2. `ЕГЭ`;
3. `Олимпиада`;
4. `Курс`;
5. `Поступление`;
6. `Личные дела`.

Предмет обязателен для направлений `Школа`, `ЕГЭ`, `Олимпиада` и `Курс`.

Для направлений `Поступление` и `Личные дела` предмет необязателен. Пользователь может выбрать предмет либо оставить значение «Без предмета».

## 7. Учебные предметы

По умолчанию доступны два предмета:

- `Русский язык`;
- `Математика`.

Пользователь может добавлять дополнительные предметы через отдельную форму.

Правила добавления предмета:

1. Название обязательно.
2. Пробелы в начале и конце удаляются.
3. Строка только из пробелов не сохраняется.
4. Нельзя добавить предмет, который уже существует. Сравнение выполняется без учёта регистра и после удаления внешних пробелов.
5. При ошибке показывается понятное сообщение.
6. После успешного добавления предмет появляется в списке предметов формы создания и редактирования задачи и в фильтре по предмету.
7. Дополнительные предметы сохраняются в `localStorage`.
8. Удаление и переименование предметов в MVP не предусмотрены.

Предмет, уже сохранённый в задаче, отображается как часть данных этой задачи.

## 8. Поля задачи

Форма создания и форма редактирования активной задачи содержат:

| Поле | Тип интерфейса | Обязательность | Правило |
|---|---|---|---|
| Название | текстовое поле | обязательно | после удаления внешних пробелов значение не должно быть пустым |
| Направление | список | обязательно | одно из шести направлений |
| Предмет | список | зависит от направления | обязателен для Школы, ЕГЭ, Олимпиады и Курса; необязателен для Поступления и Личных дел |
| Сложность | список или радиокнопки | обязательно | простая, средняя или сложная |
| Дедлайн | `input type="date"` | обязательно | допустима сегодняшняя, будущая или прошедшая календарная дата |

Рядом со сложностью должно отображаться количество XP, которое будет начислено за выполнение. XP нельзя вводить вручную.

## 9. Структура данных

### 9.1. Состояние приложения

Все постоянные данные хранятся в одном объекте:

```js
{
  version: 1,
  profile: {
    name: "Ирина",
    totalXp: 135,
    level: 2
  },
  additionalSubjects: ["Информатика"],
  tasks: []
}
```

Сохранённые выполненные задачи являются источником истины для XP. Значение `profile.totalXp` должно быть равно сумме `xpReward` всех задач со `status === "completed"`. При загрузке и после каждой операции с задачами `totalXp` и `level` проверяются и при необходимости пересчитываются, чтобы данные не расходились.

### 9.2. Объект задачи

Каждая задача хранится в следующем виде:

```js
{
  id: "уникальный-идентификатор",
  title: "Решить вариант ЕГЭ",
  direction: "ЕГЭ",
  subject: "Математика",
  difficulty: "medium",
  xpReward: 20,
  status: "active",
  originalDeadline: "2026-07-15",
  currentDeadline: "2026-07-18",
  postponementCount: 1,
  xpAwarded: false,
  createdAt: "2026-07-11T04:00:00.000Z"
}
```

Правила полей:

- `id` — уникальная строка, создаваемая при добавлении задачи;
- `title` — очищенное от внешних пробелов название;
- `direction` — одно из шести допустимых направлений;
- `subject` — название предмета или `null`, если предмет необязателен и не выбран;
- `difficulty` — `easy`, `medium` или `hard`;
- `xpReward` — фиксированное значение, соответствующее сложности;
- `status` — только `active` или `completed`;
- `originalDeadline` — первоначальный дедлайн, никогда не изменяется после создания;
- `currentDeadline` — актуальный дедлайн;
- `postponementCount` — целое число от нуля;
- `xpAwarded` — признак того, что XP за задачу уже начислен;
- `createdAt` — дата и время создания в формате ISO.

Инварианты данных:

- у активной задачи `status === "active"` и `xpAwarded === false`;
- у выполненной задачи `status === "completed"` и `xpAwarded === true`;
- `profile.totalXp` равен сумме `xpReward` всех сохранённых выполненных задач;
- `profile.totalXp` не может быть отрицательным;
- `profile.level` всегда вычисляется из актуального `profile.totalXp`.

Статусы срока `Сегодня` и `Просрочено` не сохраняются в объекте: они вычисляются при каждом отображении из `status`, `currentDeadline` и текущей локальной даты.

## 10. Создание задачи

Сценарий создания:

1. Пользователь нажимает «+ Новая задача» в заголовке блока «Активные задачи»; под заголовком раскрывается форма, а `aria-expanded` кнопки получает значение `true`.
2. Повторное нажатие на кнопку или клавиша Escape закрывает форму и синхронизирует `aria-expanded` со значением `false`.
3. Пользователь заполняет форму.
4. При смене направления приложение обновляет обязательность предмета.
5. При смене сложности приложение обновляет предварительный XP.
6. Пользователь нажимает «Добавить задачу».
7. Выполняется валидация всех полей.
8. При ошибке задача не создаётся, форма остаётся открытой, введённые значения сохраняются, а возле соответствующего поля показывается понятное сообщение.
9. При успехе создаётся новая активная задача:
   - `originalDeadline` и `currentDeadline` получают выбранную дату;
   - `postponementCount` равен `0`;
   - `status` равен `active`;
   - `xpAwarded` равен `false`;
   - `xpReward` определяется сложностью.
10. Задача сохраняется в `localStorage` и сразу появляется первой в списке активных задач.
11. Форма очищается до начального состояния и закрывается, `aria-expanded` получает значение `false`, пользователю показывается сообщение «Задача сохранена».

Расположение элементов на компьютере:

1. название — на всю ширину;
2. направление и предмет — две колонки;
3. сложность и дедлайн — две колонки;
4. награда и кнопка «Добавить задачу» — две колонки.

На телефоне название, направление, предмет, сложность, дедлайн, награда и кнопка идут в одну колонку.

Прошедший дедлайн разрешён. Такая активная задача сразу отображается как просроченная.

Новая задача добавляется в начало массива `tasks`. Поэтому без дополнительной сортировки более новые задачи отображаются выше более старых внутри соответствующего списка.

## 11. Редактирование задачи

Редактировать можно только активные задачи.

1. Пользователь нажимает «Редактировать» на карточке.
2. Открывается форма, заполненная текущими значениями задачи.
3. Можно изменить название, направление, предмет, сложность и текущий дедлайн.
4. Кнопка «Отмена» закрывает редактирование без изменения объекта задачи и без записи в `localStorage`.
5. Кнопка «Сохранить» сначала запускает те же правила валидации, что и при создании.
6. При ошибке исходная задача не изменяется.
7. При успехе изменения записываются в объект и `localStorage`, затем карточка перерисовывается.

Если при смене направления предмет становится обязательным, сохранить задачу без предмета нельзя. Если направление меняется на `Поступление` или `Личные дела`, ранее выбранный предмет можно сохранить либо явно выбрать «Без предмета».

Изменение сложности обновляет `xpReward`. Поскольку редактировать можно только активную задачу, новое значение XP будет начислено один раз при её будущем выполнении.

Выполненные задачи не имеют кнопки редактирования и не могут быть возвращены в активные в рамках MVP.

## 12. Изменение дедлайна и подсчёт переносов

При редактировании сравниваются две даты:

- старое сохранённое значение `currentDeadline` до открытия редактирования;
- новое значение дедлайна в момент нажатия «Сохранить».

Точное правило:

```text
если newCurrentDeadline > oldCurrentDeadline,
то postponementCount = postponementCount + 1;
иначе postponementCount не изменяется.
```

Сравниваются календарные даты формата `YYYY-MM-DD`, а не время суток.

Следствия:

- перенос на любую более позднюю дату увеличивает счётчик ровно на 1;
- перенос сразу на несколько дней всё равно увеличивает счётчик только на 1;
- изменение на более раннюю дату не увеличивает и не уменьшает счётчик;
- сохранение той же даты не меняет счётчик;
- изменение названия, направления, предмета или сложности не меняет счётчик;
- сколько бы раз пользователь ни менял дату в открытой форме, учитывается только итоговая дата при одном нажатии «Сохранить»;
- если пользователь выбрал более позднюю дату, затем до сохранения вернул старую или более раннюю, перенос не засчитывается;
- отмена редактирования не меняет счётчик;
- неуспешная валидация не меняет счётчик;
- `originalDeadline` после создания никогда не изменяется.

В карточке информация о переносах скрывается при нуле. При положительном значении используется нейтральная подпись `Переносов дедлайна: N`, где `N` — значение `postponementCount`.

## 13. Дедлайн и статус срока

Дедлайн хранится как календарная дата `YYYY-MM-DD` без времени суток и отображается пользователю в формате `ДД.ММ.ГГГГ`. Для отображения строка разбирается на компоненты года, месяца и дня; прямое преобразование через `new Date(currentDeadline)` не используется, чтобы дата не сдвигалась из-за часового пояса.

Сегодняшняя дата формируется из локальных компонентов `getFullYear()`, `getMonth()` и `getDate()`. После проверки формата статусы `Сегодня` и `Просрочено` можно определять сравнением нормализованных строк `YYYY-MM-DD`.

Для вычисления количества календарных дней каждая дата преобразуется в независимый от часового пояса целочисленный индекс дня:

```text
dayIndex = Date.UTC(year, month - 1, day) / 86400000
daysDifference = deadlineDayIndex - todayDayIndex
```

Для дедлайна используются компоненты сохранённой строки, а для сегодняшней даты — локальные компоненты браузера. Нельзя вычислять разницу вычитанием текущего времени из локальной полуночи: время суток и переходы между часовыми поясами или сезонным временем не должны влиять на результат.

При отображении действует приоритет:

1. Если `status === "completed"`, показывается `Выполнено`.
2. Иначе, если дедлайн раньше сегодняшней локальной даты, показывается `Просрочено`.
3. Иначе, если дедлайн равен сегодняшней дате, показывается `Сегодня`.
4. Иначе показывается количество полных календарных дней до дедлайна.

Примеры для активной задачи:

- дедлайн завтра — `Остался 1 день`;
- дедлайн через три календарных дня — `Осталось 3 дня`;
- дедлайн сегодня — `Сегодня`;
- дедлайн вчера — `Просрочено на 1 день`.

Просроченная задача должна отличаться рамкой или акцентным оттенком и обязательно иметь текст `Просрочено`; цвет не может быть единственным индикатором.

Значение строки «Срок» выводится полужирным или жирным и визуально заметнее остальных данных. Для будущего срока используется существующий красно-коричневый акцент проекта. Для дедлайна сегодня и просрочки используется существующий цвет ошибки. Новые цвета не добавляются.

После выполнения задача показывает нейтральный текст `Выполнено`, считается выполненной, даже если её дедлайн был просрочен, и не попадает в фильтр `Просроченные`.

## 14. Сложность, XP и уровни

| Сложность | Значение в данных | XP |
|---|---|---:|
| Простая | `easy` | 5 |
| Средняя | `medium` | 20 |
| Сложная | `hard` | 50 |

Начальный прогресс нового пользователя:

- общий XP — `0`;
- уровень — `1`;
- прогресс уровня — `0 из 100 XP`;
- до следующего уровня — `100 XP`.

Формулы:

```text
level = floor(totalXp / 100) + 1
xpInsideLevel = totalXp % 100
xpToNextLevel = 100 - xpInsideLevel
progressPercent = xpInsideLevel
```

При `totalXp = 135`: уровень 2, прогресс 35 из 100, до следующего уровня 65 XP, заполнение шкалы 35%.

Общий XP увеличивается при выполнении задачи и уменьшается при удалении выполненной задачи. Во всех остальных операциях XP не меняется. XP не может быть меньше нуля. Максимальный уровень в MVP не ограничен.

## 15. Выполнение задачи

1. Кнопка «Выполнено» есть только у активной задачи.
2. При нажатии приложение проверяет `status` и `xpAwarded`.
3. Если задача активна и XP ещё не начислен:
   - `xpAwarded` становится `true`;
   - `status` становится `completed`;
   - `profile.totalXp` пересчитывается как сумма `xpReward` всех сохранённых выполненных задач; в корректном состоянии это увеличивает общий XP ровно на `xpReward` выполненной задачи;
   - уровень пересчитывается по формуле;
   - всё состояние сохраняется одним обновлением в `localStorage`;
   - профиль и списки перерисовываются.
4. Выполненная задача перемещается из списка активных в список выполненных.
5. У выполненной задачи нет кнопок «Выполнено» и «Редактировать».

Повторное начисление XP за одну задачу невозможно, в том числе после перезагрузки страницы. Защиту обеспечивают одновременно `status` и `xpAwarded`.

## 16. Удаление задачи

Удалять можно активные и выполненные задачи.

1. Пользователь нажимает «Удалить».
2. Приложение показывает стандартное подтверждение `window.confirm` с названием задачи. Для выполненной задачи текст дополнительно предупреждает, сколько XP будет вычтено.
3. При отмене ничего не меняется.
4. При подтверждении активная задача удаляется из массива без изменения XP.
5. При подтверждении удаления выполненной задачи:
   - задача удаляется из массива;
   - `profile.totalXp` пересчитывается как сумма `xpReward` оставшихся выполненных задач;
   - в корректном состоянии это уменьшает общий XP ровно на `xpReward` удалённой задачи;
   - применяется нижняя граница `0`, поэтому XP не может стать отрицательным;
   - уровень и прогресс пересчитываются по формулам раздела 14.
6. Изменённое состояние сохраняется одним обновлением в `localStorage`, затем профиль, календарь и списки перерисовываются.

Если после вычитания XP пользователь пересекает границу уровня, уровень уменьшается. Например, удаление выполненной средней задачи при 110 XP приводит к 90 XP и снижению уровня с 2 до 1. Повторно вычесть XP за удалённую задачу невозможно, поскольку после удаления её больше нет в состоянии приложения.

## 17. Карточка задачи

Карточка должна показывать без дополнительного открытия:

- название;
- направление;
- предмет; при `subject === null` выводится `Без предмета`;
- сложность;
- XP за выполнение;
- текущий дедлайн в формате `ДД.ММ.ГГГГ`;
- оставшееся время или просрочку;
- статус только в виде бейджа `Активная` или `Выполнена`;
- количество переносов, если оно больше нуля.

Для активной задачи доступны кнопки `Выполнено`, `Редактировать`, `Удалить`. Для выполненной — только `Удалить`.

Отдельная строка `Статус задачи: Активная` или `Статус задачи: Выполнена` не выводится. Просроченная активная задача дополнительно получает бейдж `Просрочено`.

На компьютере первая строка карточки содержит название задачи и бейджи. Далее используется фиксированная сетка из двух колонок и трёх строк:

| Левая колонка | Правая колонка |
|---|---|
| Направление | Предмет |
| Дедлайн | Срок |
| Сложность | Награда |

На телефоне данные идут в одну колонку строго в порядке: направление, предмет, дедлайн, срок, сложность, награда.

Активная задача использует существующий светлый фон `#F3E9D7`, ранее использованный просроченной карточкой. Просроченная задача использует существующий более тёмный фон `#D6BFA6`, ранее использованный активной карточкой. Просроченная задача также сохраняет текстовый бейдж `Просрочено`, заметную границу и текст с количеством дней просрочки. Статус не передаётся только цветом, новые цвета не добавляются.

Карточка не должна быть перегружена декором. Длинные названия и значения должны переноситься, не перекрывать бейджи и не создавать горизонтальную прокрутку.

## 18. Фильтры

Фильтры располагаются в компактной панели, которая раскрывается по кнопке «Фильтры задач» в заголовке блока «Активные задачи». Повторное нажатие и клавиша Escape закрывают панель. Атрибут `aria-expanded` кнопки всегда соответствует открытому или закрытому состоянию панели.

Фильтр по статусу содержит:

- `Все`;
- `Активные`;
- `Выполненные`;
- `Просроченные`.

Фильтр по направлению содержит:

- `Все направления`;
- `Школа`;
- `ЕГЭ`;
- `Олимпиада`;
- `Курс`;
- `Поступление`;
- `Личные дела`.

Фильтр по предмету содержит:

- `Все предметы`;
- `Без предмета`;
- `Русский язык`;
- `Математика`;
- все значения из `additionalSubjects`.

Значение `Без предмета` соответствует только задачам с `subject === null`. После добавления дополнительного предмета он сразу появляется в фильтре предметов.

Три фильтра применяются одновременно по правилу AND: статус AND направление AND предмет. Например, `Просроченные` + `Курс` + `Математика` показывает только активные просроченные задачи направления `Курс` с предметом `Математика`.

Правила отображения:

- `Все` — активные задачи показываются в разделе активных, выполненные в разделе выполненных;
- `Активные` — показывается только раздел активных;
- `Выполненные` — показывается только раздел выполненных;
- `Просроченные` — показываются только активные задачи с дедлайном раньше сегодняшней даты;
- фильтры направления и предмета дополнительно ограничивают любой выбранный статус;
- при отсутствии совпадений показывается отдельное понятное пустое состояние.

Любое изменение фильтра сразу обновляет активный и выполненный списки. Фильтры влияют только на отображение, не меняют `tasks` и `localStorage` и не обязаны сохраняться после перезагрузки. Поиск и дополнительная сортировка в MVP отсутствуют.

В правом верхнем углу панели располагается визуально отделённая от трёх `select` компактная квадратная кнопка сброса. Требования к кнопке:

- видимый символ — строго `×`, а не буква `Х`;
- `type="button"`;
- `aria-label="Сбросить фильтры"`;
- `title="Сбросить фильтры"`;
- кнопка не закрывает панель фильтров.

При нажатии статус устанавливается в `Все`, направление — в `Все направления`, предмет — в `Все предметы`; активный и выполненный списки обновляются немедленно. Панель остаётся открытой, пользовательское состояние сворачивания активного списка не изменяется. Если после сброса появились подходящие активные задачи, кнопка сворачивания списка снова отображается.

Когда все три фильтра уже имеют значения по умолчанию, кнопка сброса имеет атрибут `disabled`. Отключённое состояние должно быть визуально понятным и использовать только существующую палитру. Состояние кнопки пересчитывается после изменения любого фильтра, после сброса, после заполнения списка дополнительных предметов и после каждой перерисовки интерфейса.

Сброс и переключение фильтров не изменяют `tasks`, `localStorage` или `sessionStorage`. Панель по-прежнему закрывается только повторным нажатием «Фильтры задач» или клавишей Escape.

## 19. Календарное представление

Календарь является обязательным обзорным блоком одного месяца. Он не заменяет основные списки задач и не используется для создания, редактирования или переноса задач.

### 19.1. Состав календаря

Календарь показывает один календарный месяц и содержит:

- заголовок с названием месяца и годом на русском языке;
- кнопку `Предыдущий месяц`;
- кнопку `Сегодня`;
- кнопку `Следующий месяц`;
- строку дней недели с понедельника по воскресенье;
- сетку дней выбранного месяца;
- активные задачи, размещённые в ячейке их `currentDeadline`.

При первой загрузке показывается текущий месяц и выбирается сегодняшний день. `Предыдущий месяц` и `Следующий месяц` меняют отображаемый месяц на один и выбирают первый день открытого месяца. После изменения выбранной даты календарь и список задач выбранного дня под ним перерисовываются из актуального состояния; искусственно генерировать событие клика не требуется. `Сегодня` возвращает календарь к текущему месяцу, выбирает сегодняшнюю дату и также обновляет список выбранного дня. Выбранные месяц и день не сохраняются в `localStorage`.

### 19.2. Данные календаря

В календаре отображаются только задачи со `status === "active"`. Выполненные задачи не показываются: отчёт по ним планируется за границами MVP.

Порядок задач внутри одного дня соответствует порядку в массиве `tasks`, то есть более новые находятся выше.

На компьютере, при ширине окна от 768 пикселей:

- в ячейке дня показываются названия активных задач;
- макет ячейки резервирует место не более чем для трёх однострочных названий;
- если задач больше трёх, после третьего названия показывается строка `+ ещё N`, где `N` — количество остальных задач;
- длинное название занимает одну строку и обрезается многоточием, не расширяя ячейку.

На телефоне, при ширине окна до 767 пикселей включительно:

- названия задач внутри ячеек не показываются;
- в дне с задачами показывается компактный индикатор с точным количеством активных задач;
- нажатие на ячейку выбирает этот день;
- выбранный день имеет заметное визуальное и доступное текстовое обозначение;
- под календарной сеткой показывается список всех активных задач выбранного дня;
- в списке выбранного дня показываются название, направление и статус срока каждой задачи;
- если в выбранный день активных задач нет, показывается текст `На этот день активных задач нет`.

Сегодняшний день должен иметь отдельное визуальное обозначение и текстовую или доступную подпись `Сегодня`. Просроченные задачи должны иметь не только цветовое отличие, но и текстовый признак.

Календарь перерисовывается после создания, редактирования, выполнения и удаления задачи. Фильтры основных списков на календарь не влияют: календарь всегда показывает все активные задачи выбранного месяца.

### 19.3. Ограничения календаря

Календарь является только обзорным:

- выбор дня на телефоне изменяет только обзорный список под календарём и не изменяет данные задачи;
- нельзя создавать задачу из ячейки дня;
- нельзя редактировать задачу в календаре;
- нельзя переносить задачу перетаскиванием;
- нет недельного и дневного режимов;
- нет отчёта по выполненным задачам.

## 20. Валидация и обработка ошибок

Общие правила:

- все текстовые значения очищаются от внешних пробелов;
- ошибки показываются текстом рядом с соответствующим полем;
- цвет не является единственным способом обозначения ошибки;
- при ошибке форма не закрывается и постоянные данные не изменяются;
- после исправления значения сообщение об ошибке должно исчезать при следующей проверке;
- сообщения должны быть понятными, например: `Введите название задачи`, `Выберите предмет`, `Выберите дедлайн`.

Проверки задачи:

1. Непустое название.
2. Направление входит в допустимый список.
3. Для Школы, ЕГЭ, Олимпиады и Курса выбран существующий предмет.
4. Для Поступления и Личных дел предмет либо отсутствует, либо входит в список существующих предметов.
5. Сложность входит в допустимый список.
6. Дедлайн указан и является корректной календарной датой формата `YYYY-MM-DD`.

Прошедшая дата не является ошибкой.

Если данные в `localStorage` отсутствуют, создаётся начальное состояние. Если JSON повреждён или структура критически некорректна, приложение не должно аварийно завершаться: используется безопасное начальное состояние и снова запрашивается имя. Интерфейс сброса или восстановления повреждённых данных в MVP не требуется.

## 21. Хранение в localStorage

Используется один ключ:

```text
levelUpState
```

По этому ключу сохраняется JSON-строка объекта из раздела 9.

Сохранение выполняется после:

- первого ввода имени;
- добавления предмета;
- создания задачи;
- сохранения редактирования;
- выполнения задачи;
- подтверждённого удаления задачи.

После загрузки страницы приложение:

1. читает `levelUpState`;
2. безопасно разбирает JSON;
3. проверяет наличие основных полей;
4. пересчитывает общий XP как сумму `xpReward` всех сохранённых выполненных задач;
5. пересчитывает уровень и прогресс из актуального общего XP;
6. показывает стартовую форму, если корректное имя отсутствует;
7. иначе отображает профиль, задачи и дополнительные предметы.

`localStorage` действует только в текущем браузере и на текущем устройстве. Синхронизация, резервное копирование и восстановление после очистки хранилища отсутствуют.

## 22. Адаптивность и оформление

Визуальный стиль — спокойный пастельный интерфейс в коричневых оттенках:

- светлый кремовый фон;
- бежевые карточки;
- тёмно-коричневый текст;
- карамельные, кофейные и приглушённые терракотовые акценты;
- мягкие границы и скругления;
- достаточный контраст.

Требования для телефона:

- одна колонка основных блоков и карточек;
- компактная квадратная кнопка сворачивания остаётся рядом с заголовком «Активные задачи» и не переносится в ряд крупных управляющих кнопок;
- форма создания и панель фильтров раскрываются внутри блока «Активные задачи» и располагают элементы в одну колонку;
- кнопка сброса фильтров остаётся компактной квадратной кнопкой в правом верхнем углу панели, не растягивается на всю ширину и не перекрывает подписи или поля;
- данные карточки идут в порядке: направление, предмет, дедлайн, срок, сложность, награда;
- отсутствие горизонтальной прокрутки страницы;
- элементы формы не выходят за экран;
- текст переносится;
- кнопки достаточно крупные для нажатия пальцем;
- действия на карточке могут переноситься на несколько строк или располагаться столбцом.
- кнопки управления календарём могут переноситься на несколько строк;
- календарная сетка сохраняет семь равных колонок, но использует компактные индикаторы количества задач вместо названий;
- список задач выбранного дня располагается под календарём;
- календарь и его содержимое не создают горизонтальную прокрутку страницы.

Требования для компьютера:

- контент ограничен по максимальной ширине и не растягивается на весь большой экран;
- блок «Активные задачи» занимает всю доступную ширину, а кнопки «+ Новая задача» и «Фильтры задач» находятся в его заголовке;
- форма создания использует согласованную сетку полей, панель фильтров располагает три фильтра компактно;
- кнопка сброса фильтров визуально отделена от трёх `select` и остаётся компактной квадратной кнопкой;
- карточка использует фиксированную сетку из двух колонок: направление и предмет, дедлайн и срок, сложность и награда;
- допускается сетка из нескольких колонок;
- основные действия видны без дополнительных переходов;
- карточки остаются читаемыми.
- календарь показывает до трёх названий задач в ячейке дня и строку `+ ещё N` для остальных.

Допустимы только лёгкие необязательные анимации: заполнение XP-шкалы, появление карточки, реакция на выполнение и открытие редактирования. При `prefers-reduced-motion: reduce` анимации должны быть отключены или сведены к минимуму.

## 23. Пользовательские сценарии

### Сценарий 1. Первый запуск

1. Пользователь открывает приложение без сохранённых данных.
2. Видит обязательную форму имени.
3. Вводит имя и нажимает «Начать».
4. Видит основной экран, уровень 1 и 0 XP.
5. После перезагрузки имя сохраняется, повторный запрос не появляется.

### Сценарий 2. Создание учебной задачи

1. Пользователь нажимает «+ Новая задача» и открывает форму.
2. Вводит название.
3. Выбирает `Курс`.
4. Выбирает предмет.
5. Выбирает сложность `Средняя` и видит 20 XP.
6. Выбирает дедлайн.
7. Сохраняет задачу, видит сообщение «Задача сохранена», закрытие формы и новую задачу первой в активных.

### Сценарий 3. Создание личной задачи без предмета

1. Пользователь выбирает `Личные дела`.
2. Оставляет `Без предмета`.
3. Заполняет остальные обязательные поля.
4. Задача успешно создаётся.

### Сценарий 4. Создание уже просроченной задачи

1. Пользователь выбирает дату раньше сегодняшней.
2. Сохраняет корректно заполненную форму.
3. Задача создаётся и сразу получает визуальный и текстовый статус `Просрочено`.

### Сценарий 5. Добавление предмета

1. Пользователь вводит новый предмет.
2. Приложение проверяет пустое значение и дубликат.
3. Новый предмет появляется в списках выбора.
4. После перезагрузки предмет остаётся доступен.

### Сценарий 6. Редактирование без переноса

1. Пользователь открывает активную задачу.
2. Меняет название или сложность, оставляя дедлайн прежним.
3. Сохраняет изменения.
4. Данные обновляются, счётчик переносов не меняется.

### Сценарий 7. Перенос дедлайна

1. Текущий дедлайн задачи — 15 июля.
2. Пользователь открывает редактирование и сохраняет 18 июля.
3. `currentDeadline` становится 18 июля.
4. `originalDeadline` остаётся 15 июля.
5. `postponementCount` увеличивается ровно на 1.

### Сценарий 8. Изменение дедлайна на более ранний

1. Текущий дедлайн — 18 июля.
2. Пользователь сохраняет 16 июля.
3. Текущий дедлайн меняется, счётчик переносов не увеличивается и не уменьшается.

### Сценарий 9. Отмена редактирования

1. Пользователь меняет несколько полей в форме.
2. Нажимает «Отмена».
3. Карточка и данные в `localStorage` остаются без изменений.

### Сценарий 10. Выполнение и повышение уровня

1. У пользователя 80 XP.
2. Он выполняет среднюю задачу за 20 XP.
3. Общий XP становится 100.
4. Уровень становится 2, прогресс уровня — 0 из 100.
5. Задача перемещается в выполненные.
6. Повторно получить XP за неё нельзя.

### Сценарий 11. Фильтрация

1. Пользователь нажимает «Фильтры задач» и открывает компактную панель.
2. Выбирает `Просроченные`.
3. Затем выбирает направление `Школа`.
4. Выбирает предмет `Математика`.
5. Видит только активные просроченные школьные задачи по математике.
6. Изменение фильтров не удаляет и не изменяет задачи и не записывает `localStorage`.

### Сценарий 12. Удаление

1. Пользователь нажимает «Удалить».
2. При отмене задача остаётся.
3. При подтверждении задача исчезает и удаляется из `localStorage`.
4. Если задача активная, XP не меняется.
5. Если задача выполненная, она удаляется из массива, общий XP пересчитывается по оставшимся выполненным задачам и уменьшается ровно на `xpReward` удалённой задачи.
6. После удаления выполненной задачи уровень и шкала пересчитываются, а XP не может стать отрицательным.

### Сценарий 13. Просмотр календаря

1. Пользователь видит текущий месяц, неделю с понедельника и только активные задачи в днях их дедлайнов.
2. Нажимает `Следующий месяц`, переходит на один месяц вперёд и выбирает первое число открытого месяца.
3. На телефоне список под календарём сразу показывает активные задачи выбранного первого числа или сообщение об их отсутствии.
4. Нажимает `Предыдущий месяц`, переходит на один месяц назад и снова выбирает первое число открытого месяца.
5. Нажимает `Сегодня`, возвращается к текущему месяцу и выбирает сегодняшнюю дату.
6. Выполненные задачи в календаре не отображаются.
7. На компьютере видит до трёх названий в ячейке и `+ ещё N`, если задач больше.
8. На телефоне видит количество задач в ячейке, выбирает день и просматривает список его активных задач под календарём.
9. Календарь не позволяет создать, отредактировать или перетащить задачу.

## 24. Критерии приёмки

MVP принимается, если одновременно выполняются все условия:

### Первый запуск и профиль

- Без сохранённого имени основной интерфейс не открывается.
- Пустое имя не принимается.
- Корректное имя сохраняется и восстанавливается после перезагрузки.
- Новый пользователь начинает с уровня 1 и 0 XP.
- Профиль корректно показывает общий XP, уровень, прогресс и XP до следующего уровня.

### Задачи и предметы

- Форма создания открывается кнопкой «+ Новая задача», закрывается повторным нажатием или Escape и синхронизирует `aria-expanded`.
- При наличии подходящих активных задач компактная квадратная кнопка сворачивает и разворачивает только область карточек активного списка.
- Кнопка показывает `−` в развёрнутом состоянии и `+` в свёрнутом, синхронизирует `aria-expanded` и меняет `aria-label` между `Свернуть активные задачи` и `Развернуть активные задачи`.
- При отсутствии подходящих активных задач кнопка сворачивания скрыта.
- Сворачивание не изменяет `tasks` и `localStorage`; после перезагрузки список развёрнут.
- После успешного создания задачи активный список автоматически разворачивается и показывает новую карточку первой.
- Ошибка не закрывает форму и не очищает корректные значения; успешное создание очищает и закрывает форму и показывает сообщение «Задача сохранена».
- Можно создать задачу с каждым из шести направлений.
- Для Школы, ЕГЭ, Олимпиады и Курса предмет обязателен.
- Для Поступления и Личных дел задача создаётся без предмета.
- По умолчанию доступны Русский язык и Математика.
- Можно добавить непустой уникальный предмет.
- Дубликат предмета без учёта регистра не добавляется.
- Дополнительные предметы сохраняются после перезагрузки.
- Прошедший дедлайн разрешён и сразу отображается как просроченный.
- Невалидная форма не создаёт и не изменяет задачу.

### Редактирование и переносы

- Редактируются только активные задачи.
- Изменения применяются только после сохранения.
- Отмена не изменяет данные.
- Более поздний дедлайн увеличивает счётчик ровно на 1 за одно сохранение.
- Та же или более ранняя дата не увеличивает счётчик.
- Изменение других полей не влияет на счётчик.
- `originalDeadline` не меняется.
- Счётчик и текущий дедлайн сохраняются после перезагрузки.
- При положительном счётчике карточка показывает `Переносов дедлайна: N`.

### Выполнение, XP и уровни

- Простая задача даёт 5 XP, средняя 20 XP, сложная 50 XP.
- XP начисляется только при первом выполнении активной задачи.
- Повторное нажатие и перезагрузка страницы не начисляют XP за выполненную задачу повторно.
- Выполненная задача перемещается в отдельный список.
- Выполненную задачу нельзя редактировать или выполнить повторно.
- Каждые 100 общего XP повышают уровень согласно формуле.
- Прогресс внутри уровня вычисляется через остаток от деления на 100.
- Удаление выполненной задачи вычитает ровно её `xpReward` из общего XP.
- После вычитания XP уровень и шкала прогресса пересчитываются, а XP не становится отрицательным.
- Общий XP равен сумме `xpReward` всех сохранённых выполненных задач.
- Удаление выполненной средней задачи при 110 XP приводит к 90 XP и снижению уровня с 2 до 1.
- XP, статус и уровень сохраняются после перезагрузки.

### Сроки и фильтры

- Активные задачи различают будущий дедлайн, сегодня и просрочку.
- Просрочка определяется по локальной календарной дате.
- Дедлайн в карточке отображается в формате `ДД.ММ.ГГГГ` без сдвига календарной даты из-за часового пояса.
- Для дедлайнов вчера, сегодня и завтра отображаются соответственно просрочка, `Сегодня` и один оставшийся календарный день, в том числе на границе месяца.
- Просроченная задача имеет текстовый статус и визуальное выделение.
- Активная карточка использует фон `#F3E9D7`, просроченная — `#D6BFA6`; новые цвета не добавляются.
- Строка `Срок` выделена начертанием и существующим акцентом, а выполненная задача показывает нейтральное `Выполнено`.
- Выполненная задача не считается просроченной в фильтре.
- Карточка всегда содержит строку предмета и показывает `Без предмета` при `subject === null`.
- Статус показывается бейджем без отдельной строки; просроченная активная задача дополнительно имеет бейдж `Просрочено`.
- На компьютере данные карточки образуют фиксированную сетку из двух колонок, на телефоне идут в согласованном порядке в одну колонку.
- Панель фильтров открывается кнопкой «Фильтры задач», закрывается повторным нажатием или Escape и синхронизирует `aria-expanded`.
- Три фильтра содержат все предусмотренные значения, включая `Без предмета` и дополнительные предметы.
- Фильтры статуса, направления и предмета работают совместно по правилу AND.
- Переключение фильтров сразу обновляет оба списка, не изменяет `tasks` и не записывает `localStorage`.
- Кнопка сброса показывает символ `×`, имеет `type="button"`, `aria-label="Сбросить фильтры"` и `title="Сбросить фильтры"`.
- При значениях `Все`, `Все направления` и `Все предметы` кнопка сброса отключена; изменение одного или всех трёх фильтров включает её.
- Нажатие кнопки сбрасывает все три фильтра, немедленно возвращает полный список, оставляет панель открытой и не изменяет состояние сворачивания активного списка.
- Сброс не изменяет `tasks`, `localStorage` или `sessionStorage`; если активные задачи снова появились, кнопка сворачивания списка снова отображается.
- На компьютере и телефоне кнопка остаётся компактной, не перекрывает элементы панели и не создаёт горизонтальную прокрутку.

### Календарь

- При запуске календарь показывает текущий месяц.
- Работают кнопки `Предыдущий месяц`, `Сегодня` и `Следующий месяц`.
- После перехода к предыдущему или следующему месяцу выбирается первое число открытого месяца; на телефоне список под календарём сразу обновляется для этого дня.
- После нажатия `Сегодня` на телефоне список под календарём сразу обновляется для сегодняшней даты.
- Неделя начинается с понедельника.
- Активная задача показана в дне своего текущего дедлайна.
- После изменения дедлайна задача перемещается в правильный день календаря.
- После выполнения или удаления задача исчезает из календаря.
- Выполненные задачи в календаре не показываются.
- Фильтры списков не изменяют содержимое календаря.
- Календарь не позволяет создавать, редактировать или перетаскивать задачи.
- На компьютере в ячейке показаны не более трёх названий и `+ ещё N` для остальных задач.
- На телефоне в ячейке показано количество задач, а полный список выбранного дня расположен под календарём.
- На телефоне выбор дня не изменяет данные задачи.
- Календарь не вызывает горизонтальную прокрутку страницы.

### Удаление, хранение и интерфейс

- Удаление всегда требует подтверждения.
- Отмена подтверждения ничего не меняет.
- Все постоянные данные хранятся под ключом `levelUpState`.
- После перезагрузки корректные данные восстанавливаются.
- Невалидная JSON-строка под ключом `levelUpState` не приводит к падению приложения: используется безопасное начальное состояние и снова запрашивается имя.
- На компьютере интерфейс остаётся ограниченным по ширине и читаемым.
- На телефоне блоки идут в одну колонку и нет горизонтальной прокрутки.
- На контрольных ширинах 767 и 768 пикселей календарь и остальные блоки не создают горизонтальную прокрутку страницы.
- Статусы и ошибки понятны не только по цвету.
- Приложение работает как статическая страница из `index.html`, `style.css` и `script.js`.

## 25. Что не входит в MVP

В этой версии запрещено добавлять:

- регистрацию и авторизацию;
- несколько пользователей или профилей;
- изменение имени после первого запуска;
- сервер и базу данных;
- синхронизацию между устройствами;
- резервное копирование, экспорт и импорт;
- совместную работу;
- системные, почтовые и push-уведомления;
- интеграцию с электронным дневником;
- импорт расписания, дат ЕГЭ и олимпиад;
- недельный и дневной режимы календаря;
- создание, редактирование и перенос задач через календарь;
- отчёт по выполненным задачам;
- интерактивную временную шкалу;
- поиск и сложную сортировку;
- удаление и переименование дополнительных предметов;
- возврат выполненной задачи в активные;
- редактирование выполненной задачи;
- историю всех изменений дедлайна;
- статистику, недельные обзоры и цели по предметам;
- магазин наград, виртуальную валюту, аватары и достижения;
- звуковые эффекты;
- искусственный интеллект;
- мобильное приложение;
- любые функции, не описанные в этом техническом задании.

## 26. Итоговый результат

Результатом должен быть реалистичный учебный MVP: одна адаптивная страница, три основных файла, простое состояние в `localStorage` и прямолинейная логика без лишних слоёв архитектуры. Реализация должна строго следовать правилам данных, валидации, дедлайнов, переносов, XP, фильтрации и календаря из этого документа.
