# План разработки Level Up

## Цель документа

Этот документ разбивает разработку MVP Level Up на последовательные завершённые шаги. Каждый шаг должен давать работающий и проверяемый результат, соответствующий `concept.md` и `tz.md`.

План не расширяет согласованный MVP. Для реализации используются только:

- `index.html`;
- `style.css`;
- `script.js`;
- HTML;
- CSS;
- JavaScript;
- `localStorage`.

React, другие фреймворки, сервер, база данных, сборщики и дополнительные библиотеки не используются.

## Правила ведения plan.md как журнала разработки

1. Перед началом шага изменить его статус с `Не начат` на `В работе`.
2. Не начинать следующий шаг, пока результат текущего шага не реализован и не проверен.
3. После реализации записать под шагом фактически выполненные автоматические проверки и их результаты.
4. Автоматической считается только проверка, которую Codex действительно выполнил доступным инструментом и для которой получил наблюдаемый результат.
5. Нельзя отмечать проверку пройденной только потому, что код выглядит правильным при чтении.
6. Если в текущей среде недоступны запуск браузера, проверка его консоли, изменение ширины экрана или автоматизация пользовательских кликов, прямо записать, что проверка не выполнена автоматически, перенести её в список ручных проверок пользователя и не считать выполненной.
7. Для каждой выполненной автоматической проверки записывать использованную команду или инструмент и фактический результат, включая обнаруженные ошибки или подтверждение их отсутствия.
8. После тестов, изменяющих `localStorage`, обязательно восстановить чистое согласованное состояние приложения и зафиксировать результат восстановления.
9. Шаг нельзя переводить в статус `Завершён`, пока пользователь не подтвердил обязательные ручные проверки.
10. Если проверка не пройдена, оставить шаг в статусе `В работе` или установить `Заблокирован`, кратко указав причину.
11. После успешных автоматических проверок установить статус `На ручной проверке` и передать пользователю перечисленные ручные проверки, включая проверки, которые не удалось автоматизировать в текущей среде.
12. Статус `Завершён` устанавливать только после выполнения всех критериев завершения шага и подтверждения обязательных ручных проверок пользователем.
13. Git-точку сохранения создавать только после успешного завершения шага. Один шаг — один отдельный осмысленный commit.
14. Не добавлять в журнал новые функции, отсутствующие в `concept.md` и `tz.md`. Новые решения сначала согласовывать с пользователем.
15. При изменении требований фиксировать принятое решение в соответствующем шаге и повторно проверять затронутые завершённые шаги.

## Обозначения статусов

- `Не начат` — работа по шагу ещё не выполнялась.
- `В работе` — реализация или исправление проверок выполняется.
- `На ручной проверке` — автоматические проверки пройдены, требуется проверка пользователя.
- `Завершён` — результат реализован, проверен и может служить основой следующего шага.
- `Заблокирован` — продолжение невозможно без решения пользователя или устранения указанной причины.

## Шаг 1. Каркас приложения, первый запуск и базовое состояние

**Статус:** Завершён

### Цель шага

Получить открывающуюся адаптивную страницу с базовым пастельным оформлением, обязательным вводом имени при первом запуске, профилем начального уровня и безопасным хранением начального состояния.

### Файлы

- создать `index.html`;
- создать `style.css`;
- создать `script.js`.

### Что реализовать

- семантический каркас всех основных блоков страницы без полной функциональности последующих шагов;
- стартовую форму имени, которая блокирует основной интерфейс до ввода непустого имени;
- удаление внешних пробелов и текстовую ошибку для пустого имени;
- объект состояния версии 1 с `profile`, `additionalSubjects` и `tasks`;
- начальные значения: уровень 1, 0 XP, прогресс 0 из 100 и 100 XP до следующего уровня;
- сохранение всего постоянного состояния под единственным ключом `levelUpState`;
- безопасное чтение JSON при загрузке;
- переход к безопасному начальному состоянию и повторный запрос имени при отсутствии данных, невалидном JSON или критически некорректной структуре;
- базовую адаптивную компоновку без горизонтальной прокрутки;
- основу согласованной кремово-бежевой и коричневой цветовой системы.

### Результат шага

Приложение открывается напрямую через `index.html`. Новый пользователь вводит имя и видит основной экран с профилем уровня 1 и 0 XP. После перезагрузки имя и начальное состояние восстанавливаются.

### Автоматические проверки Codex

Все проверки ниже выполняются автоматически только при наличии подходящего доступного инструмента. Для каждой выполненной проверки в журнал записываются инструмент или команда и фактический результат. Проверки, которые нельзя выполнить инструментально, переносятся в ручные проверки пользователя и не считаются пройденными автоматически.

- проверить синтаксис `script.js`;
- при наличии управления браузером проверить консоль при первой и повторной загрузке; иначе передать проверку пользователю;
- при наличии автоматизации браузерных кликов и ввода выполнить сценарии с пустым именем, именем из пробелов, корректным именем и повторной загрузкой; иначе передать их пользователю;
- при наличии доступа к хранилищу страницы проверить содержимое `levelUpState` после сохранения имени;
- при наличии доступа к хранилищу страницы подставить невалидную JSON-строку и наблюдаемо проверить безопасный возврат к стартовой форме;
- после проверок `localStorage` восстановить чистое согласованное состояние и зафиксировать фактический результат восстановления;
- проверить отсутствие запрещённых зависимостей и файлов;
- выполнить `git diff --check`.

### Ручные проверки пользователя

- оценить понятность стартовой формы и профиля;
- проверить читаемость базовых цветов и текста;
- открыть страницу на компьютере и телефоне и убедиться, что каркас не выходит за экран.

### Фактически реализовано

- стартовая форма имени;
- запрет пустого имени и имени из пробелов;
- сохранение корректного имени;
- профиль уровня 1 с 0 XP;
- восстановление состояния после перезагрузки;
- безопасная обработка невалидного JSON;
- единственный ключ `localStorage` — `levelUpState`;
- начальное состояние `version: 1` с `profile`, `additionalSubjects` и `tasks`;
- адаптивный каркас;
- согласованная палитра:
  - `#F3E9D7`;
  - `#D6BFA6`;
  - `#B08968`;
  - `#7A553A`;
  - `#3B2A22`;
- новая компоновка блоков:
  - «Новая задача» и «Активные задачи» в одном ряду;
  - «Календарь» на всю ширину;
  - «Фильтры» и «Выполненные задачи» в одном ряду;
- кнопка настроек в верхней панели;
- панель «Учебные предметы», открывающаяся поверх страницы;
- закрытие панели повторным нажатием на кнопку-шестерёнку;
- закрытие панели клавишей Escape;
- отсутствие сдвига основного интерфейса при открытии панели.

### Фактические результаты проверок

- пустое имя не принято;
- имя из пробелов не принято;
- имя «Анастасия» сохранено;
- после перезагрузки восстановлены имя, уровень 1 и 0 XP;
- невалидный JSON привёл к безопасному возврату на стартовый экран;
- рабочее состояние после теста восстановлено;
- при открытии через `http://localhost:8000` ошибок `script.js` в Console не обнаружено;
- обнаружен только несущественный ответ `404` для `favicon.ico`;
- Node.js в среде проверки отсутствует, поэтому `node --check` не выполнялся;
- на iPhone 14 Pro Max блоки отображаются в одну колонку;
- панель настроек не выходит за границы мобильного экрана;
- на iPad и компьютере компоновка отображается корректно;
- горизонтальная прокрутка не обнаружена;
- пользователь подтвердил оформление и расположение элементов.

### Итог ручной проверки

Обязательные ручные проверки подтверждены пользователем. Шаг 1 завершён; Git-коммит не создан и ожидает отдельного подтверждения.

### Критерии завершения

- основной интерфейс недоступен без сохранённого имени;
- пустое имя не принимается, корректное сохраняется;
- профиль показывает уровень 1 и 0 XP;
- корректное состояние восстанавливается после перезагрузки;
- повреждённое состояние не вызывает падение;
- страница работает без внешних библиотек и без ошибок консоли.

### Точка сохранения Git

После успешных проверок создать отдельный commit: `Создать каркас приложения и профиль пользователя`.

## Общий финальный чек-лист соответствия tz.md

### Технологии и границы

- [ ] Приложение состоит из `index.html`, `style.css` и `script.js`.
- [ ] Используются только HTML, CSS, JavaScript и `localStorage`.
- [ ] Нет React, других фреймворков, сборщиков, библиотек, сервера и базы данных.
- [ ] Не реализованы функции из раздела 25 `tz.md`.

### Первый запуск и профиль

- [ ] Без имени основной интерфейс не открывается.
- [ ] Пустое имя не принимается; корректное сохраняется и восстанавливается.
- [ ] Новый пользователь начинает с уровня 1 и 0 XP.
- [ ] Профиль показывает общий XP, уровень, прогресс и XP до следующего уровня.

### Направления, предметы и создание задач

- [ ] Доступны все шесть направлений.
- [ ] Русский язык и Математика доступны по умолчанию.
- [ ] Дополнительный предмет непустой, уникальный без учёта регистра и сохраняется.
- [ ] Обязательность предмета зависит от направления.
- [ ] Форма содержит все поля и не изменяет данные при ошибке.
- [ ] Прошедший дедлайн разрешён и сразу получает статус просрочки.
- [ ] Объекты задач соответствуют структуре и инвариантам раздела 9 `tz.md`.

### Даты, карточки и фильтры

- [ ] Дедлайн хранится как `YYYY-MM-DD` и показывается как `ДД.ММ.ГГГГ`.
- [ ] Расчёт календарных дней не зависит от времени суток и часового пояса.
- [ ] Вчера, сегодня и завтра корректно определяются на границе месяца.
- [ ] Карточки содержат все обязательные данные и разрешённые действия.
- [ ] Просрочка обозначается текстом и визуально.
- [ ] Фильтры статуса и направления работают совместно по AND и не меняют данные.

### Редактирование и переносы

- [ ] Редактируются только активные задачи.
- [ ] Изменения применяются только после успешного сохранения.
- [ ] Отмена и ошибки не изменяют состояние.
- [ ] Более поздний дедлайн увеличивает счётчик ровно на 1 за сохранение.
- [ ] Та же или более ранняя дата счётчик не увеличивает.
- [ ] `originalDeadline` не изменяется.
- [ ] При положительном счётчике показывается `Переносов дедлайна: N`.

### Выполнение, удаление, XP и уровни

- [ ] Простая задача даёт 5 XP, средняя 20 XP, сложная 50 XP.
- [ ] XP начисляется только при первом выполнении активной задачи.
- [ ] Повторное действие и перезагрузка не начисляют XP повторно.
- [ ] Выполненная задача не редактируется и не возвращается в активные.
- [ ] `totalXp` равен сумме наград сохранённых выполненных задач.
- [ ] Уровень и шкала вычисляются по формулам раздела 14 `tz.md`.
- [ ] Удаление активной задачи не меняет XP.
- [ ] Удаление выполненной задачи пересчитывает XP, уровень и прогресс.
- [ ] XP не может стать отрицательным.
- [ ] Любое удаление требует подтверждения, отмена ничего не меняет.

### localStorage

- [ ] Всё постоянное состояние хранится одним JSON под ключом `levelUpState`.
- [ ] Сохранение выполняется после каждой операции из раздела 21 `tz.md`.
- [ ] После загрузки проверяются основные поля, XP и уровень пересчитываются.
- [ ] Валидные данные восстанавливаются после перезагрузки.
- [ ] Невалидный JSON не приводит к падению и запускает безопасное начальное состояние.

### Месячный календарь

- [ ] При запуске открыт текущий месяц, выбран сегодняшний день.
- [ ] Неделя начинается с понедельника.
- [ ] Работают переходы по месяцам и кнопка `Сегодня`.
- [ ] После смены месяца выбирается первое число и обновляется мобильный список.
- [ ] Календарь показывает только активные задачи по `currentDeadline`.
- [ ] Выполнение, удаление и редактирование задачи обновляют календарь.
- [ ] Фильтры основных списков не влияют на календарь.
- [ ] На компьютере видны до трёх названий и `+ ещё N`.
- [ ] На телефоне видны количества и список задач выбранного дня.
- [ ] Календарь не создаёт, не редактирует и не переносит задачи.
- [ ] Нет недельного и дневного режимов.

### Адаптивность и оформление

- [ ] На компьютере контент ограничен по ширине и читаем.
- [ ] На телефоне блоки идут в одну колонку.
- [ ] На ширинах 767 и 768 пикселей нет горизонтальной прокрутки.
- [ ] Текст и действия не выходят за границы карточек и форм.
- [ ] Статусы, ошибки, сегодняшний и выбранный день понятны не только по цвету.
- [ ] Анимации необязательны и учитывают `prefers-reduced-motion`.
